## 2. 身份交接（三款共用同一套，不另造）

1. 大廳把目前玩家的 playerId 放在網址 `?bvPlayerId=`。
2. 遊戲用共用 SDK `universe/shared/universe-sdk.js` 驗證格式（`p_`＋20 碼；舊 `ID__頭像` playerKey 直接拒絕、不送 API），
   再以 `GET /v1/players/:playerId` 讀公開資料（唯讀）。
3. 沒有網址參數時：**大廳目前玩家優先**，其次才是本分頁先前的玩家（v0.2.0 調整，避免大廳已換成 B 卻沿用 A）。
4. 回大廳：`session.goLobby()` → `../../index.html`（Sandbox 為 `?sandbox=1`）。大廳用自己記住的目前玩家顯示，
   不重建玩家、不重新輸入 ID、不重選頭像；網址不帶任何身份資料。

### 節奏遊戲（universe/rhythm/，由 build_prototype.py 從正式版產生，55 處修改）

- 歌曲、Beatmap、字幕、音訊、MV 仍由原版網址唯讀載入；音樂編輯器與管理頁不複製、不混入玩家入口。
- 前端寫死的解鎖 PIN 與管理預設密碼已移除。
- 核心完整性：228 個原版函式中，只有列出的 48 個玩家資料層函式不同；其中 7 個「小修改」函式還原後與原版逐字相同；
  `<style>`、頁面結構與原版逐字相同；`PERF_MS 72／GOOD_MS 145`、鍵位保留。

### 知識挑戰（universe/quiz/，main.js 63 處、index.html 4 處修改；style.css 原樣複製）

  宇宙版維持停用、正常遊戲不會抽到（見 DATA-CONTRACTS.md 7.1）。
- 核心完整性：239 個函式中只有列出的玩家資料層函式不同；9 個「小修改」函式還原後與原版逐字相同；style.css 與頁面結構逐字相同。

## 6. 預覽、部署影響、回復

- **不合併就有正式網址的分支預覽：目前不支援。** GitHub Pages 只發布 main；本 Repository 沒有 Pages 預覽流程，也不應為了預覽改動正式網站。
- 可選的免合併試看：第三方 raw.githack.com 能直接顯示分支檔案（`https://raw.githack.com/vashyang1120/balloon-v-universe/<分支>/index.html?sandbox=1`）。
  因為網域不同，正式玩家 API 會被 CORS 擋下（這是正確的保護），**只能用 Sandbox 模式**（分頁內模擬玩家、完全不連 API）。
- 合併 main 後的影響：大廳三個入口改進宇宙版（只在 balloon-v-universe 網站內）；三款正式遊戲網站與舊 Firebase 完全不變；
  玩家 API 不變（本 PR 沒有修改 backend/）。若 Cloudflare 自動部署會在每次 main 更新時重建 Worker，重建的是同一份程式。
- 回復：在 GitHub 對合併後的 PR 按「Revert」並合併即可恢復成 v0.1.0（入口回到原本的說明視窗）；不需要動 Firebase、Cloudflare 或三款正式遊戲。
