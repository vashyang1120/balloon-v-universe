# balloon-v-universe-v0.3.1-official-data-collection-test-1

正式成績、V幣、稱號與頭像收藏整合。本文件說明：盤點結果、新增內容、分階段啟用、回復、待確認事項。

## 1. 沿用 v0.3.0，新增的部分

| 部分 | 內容 |
|---|---|
| Worker | `collection-catalog.js`（稱號＋展示頭像目錄與解鎖規則）、`collection-service.js`（TitleService＋AvatarUnlockService）、`namespace.js`（試營運 trial/ 命名空間）；成績被接受時自動解鎖；裝備 API；管理員收藏查詢、人工發放、歷史補判定、收藏 CSV、真實資料庫自我檢查、試營運清除 |
| 大廳 | 我的通行證「收藏」頁：查看與裝備稱號、展示頭像、還原預設；右上玩家卡與排行榜同步顯示 |
| 四款遊戲 | 讀同一份玩家資料（展示頭像、稱號）；遊戲內的「稱號收藏」「頭像收藏」改開共用收藏視窗（只讀，更換統一在大廳） |
| 管理後台 | 玩家收藏查詢（來源、時間、裝備）、人工發放／收回頭像、歷史補判定、收藏 CSV、正式寫入狀態、真實資料庫自我檢查、清除試營運資料 |
| 派對島 | 不需要修改（展示頭像由玩家 API 提供；分項滿分稱號由伺服器從已接受的大陸成績判定） |

## 4. 分階段啟用（不要直接改成 on）

| 階段 | 做法 | 驗證 |
|---|---|---|
| 1 | 合併 PR（開關維持 off）→ Cloudflare 自動部署 Worker | 大廳四個入口、排行榜、通行證收藏（只能查看）；管理後台能登入、顯示「正式成績：關閉」 |
| 2 | 管理後台按「真實資料庫自我檢查」 | 7 個步驟全部 ✅（寫入讀回、條件寫入成功／過期被拒、不存在才建立、同時兩個寫入只成功一個、多路徑更新、清除）。只寫 `_selftest/` 並立即刪除 |
| 3 | 小 PR：`SCORES_ENABLED="trial"`、`REWARDS_ENABLED="trial"`、`TRIAL_PLAYER_IDS="你的測試玩家 playerId"` | 測試玩家玩四款遊戲；後台查成績、審核、帳本；所有資料只寫在 `trial/`，正式排行榜與錢包不受影響 |
| 4 | 同上 | V幣 +30／+10、稱號與頭像解鎖、裝備、學生頭像授權 |
| 5 | 後台「清除試營運資料」→ 小 PR：`SCORES_ENABLED="on"`、`REWARDS_ENABLED="on"`、`TRIAL_PLAYER_IDS=""` | 正式資料從乾淨狀態開始 |

試營運期間，排行榜讀的是 `trial/`（所有人看得到測試玩家的成績）；名單外的玩家照常遊玩，成績維持本分頁測試成績。

啟用前玩過的 Mock 成績、測試 V幣，不會補寫成正式資料。

## 5. 歷史成績補判定

管理後台「玩家收藏」→「歷史成績補判定」：讀這位玩家在新遊戲宇宙已接受的正式成績，補上應有的稱號／頭像。可以重複執行（已擁有的不重複）。不讀舊 Firebase、不讀 Mock、不讀待審核或被拒絕的成績。目前正式寫入尚未開啟，所以正式環境還沒有可補判定的成績。

## 6. 回復

| 狀況 | 做法 |
|---|---|
| 試營運有問題 | 開關改回 `off`；後台清除 `trial/` |
| 全面開放後有問題 | 開關改回 `off`：立即停止寫入，資料保留 |
| 整版回復 | revert PR 的合併 commit |

## 7. 已知限制與待確認

- ID＋身份頭像不是強身份驗證：知道別人的 ID 和身份頭像，就能替他更換稱號／展示頭像（不能改成績、V幣、解鎖）。這是已接受的取捨；未來開放 V幣消費前再加強。
- 學生專屬頭像需要人工對應：舊系統的學生（涵涵、萱萱）在新系統的 playerId 不能自動推定，請在後台人工授權。
- 待決定：派對島「善良冒險家／和平大使／超勤儉冒險家」與 4 個小遊戲稱號是否改成「信任派對島結算」來發放；「氣球哥哥 3」的進度條件；節奏 Full Combo 的判定。
- 排行榜讀取 `publicProfiles` 整個節點來顯示目前頭像與稱號：玩家數千人以內沒問題。
- Cloudflare 免費方案每個請求最多 50 個子請求：一次問答成績提交約 25 個，正常情況足夠。
